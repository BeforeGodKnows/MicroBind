# 路线图

近期工作以随包 litemall 子集暴露的缺口为依据。先提高对真实代码的解释能力，再扩大自动编排范围。

| 优先级 | 工作 | 验收依据 |
| --- | --- | --- |
| 1 | 恢复 MyBatis Example 的字段、运算和值，识别自定义身份解析器，连接接口实现调用 | 原始样例中有明确证据的 `needs_review` 减少；同对象/错对象、可信/伪造身份、检查失败等正反例均有断言 |
| 2 | 稳定技能输入输出契约，增加版本、启停、超时与配置管理 | 新技能通过注册接入，无需修改 API 业务逻辑；禁用技能不可执行，结果记录所用版本 |
| 3 | 在固定工作流之外增加可选规划器 | 计划经过依赖和预算校验；比较覆盖、误报、执行成本及重放结果 |

新增真实项目样例时，先固定源码版本和业务策略，再标注预期路径。公开基准应分别报告分析覆盖、告警正确性和修复后的正常业务情况，避免仅用告警数量判断进步。

外部工具按需求接入：Joern/CodeQL 用于更完整的调用与控制流；IDA/MCP 用于 JNI 或本地二进制。技能声明、规划器、断点恢复和第三方插件隔离均属于后续工作，当前发行版未提供自动加载插件或自主规划。

服务端后续还需根据实际使用规模评估账号权限、存储配额和数据库迁移。现阶段适合可信项目组部署，不设置缺少性能测量依据的并发承诺。
